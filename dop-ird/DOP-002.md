# DOP-002 — Containerization

Project: Deploy Status Checker
Owner: Tien Nguyen (solo — no partner assigned)
Status: ACTIVE
Last audited: 2026-10-12
Parent: [DOP-001](DOP-001.md) (product) — this DOP takes over DOP-001 §7–§8.

## 1. Objective

Every Deploy Status Checker service ships as one immutable, minimal, non-root container image that runs identically on a laptop (Docker Compose), a VM, and Kubernetes. An image is identified by the git commit it was built from, so any running container can be traced back to source and any release can be rolled back by tag.

## 2. In scope

- Dockerfiles for `api-gateway`, `deploy-service`, `log-service` (one per service repo).
- Build targets: `runtime` (default, shipped) and `migrator` (Prisma `migrate deploy`, deploy/log only).
- Image registry, naming, and tagging rules.
- Local runtime: `infra/docker-compose.yml` (dev) and `infra/docker-compose.prod.yml` (prebuilt images).
- Container networking for the Compose target (`frontend` / `backend` networks).
- Build → tag → push → pull → restart → health check → rollback flow (`infra/scripts/deploy.sh`).

## 3. Out of scope

- Kubernetes objects (Deployment, Service, probes) → [DOP-003](DOP-003.md).
- Where images are hosted in AWS and who may push → [DOP-004](DOP-004.md).
- CI pipeline mechanics (jobs, triggers, scan gate) → [IRD-004](IRD-004.md).
- Image vulnerability scanning beyond `npm audit` (Trivy / SonarQube) — deferred to Week 5 CI/CD days.
- Multi-arch images: only `linux/amd64` is built for clusters (Apple Silicon builds use `--platform=linux/amd64`).

## 4. Acceptance Criteria

| AC | Criterion | Verify with | Status 2026-10-12 |
|---|---|---|---|
| AC-1 | Every service Dockerfile is multi-stage (`builder` → `runtime`) | `grep -c '^FROM' */Dockerfile` → ≥ 2 each | DONE |
| AC-2 | Base image is pinned `node:24-alpine` in every stage; no `latest` | `grep -n '^FROM' */Dockerfile` | DONE |
| AC-3 | Runtime stage runs as non-root user `app` | `docker run --rm <image> id -u` → not `0` | DONE (Dockerfile `USER app`) |
| AC-4 | Every runtime image declares a `HEALTHCHECK` against `/health` | `docker inspect --format '{{json .Config.Healthcheck}}' <image>` | DONE |
| AC-5 | Runtime image contains no `prisma` CLI and no dev dependencies | `docker run --rm <image> ls node_modules/.bin/prisma` → not found | DONE (`npm ci --omit=dev`) |
| AC-6 | Every image reference used outside local dev is tagged with a 7-char git SHA — never `latest`, never a hand-picked tag like `v1` | `grep -rn 'image:' */k8s infra/docker-compose.prod.yml` | **ACTIVE — partly fixed 2026-10-12**: app Deployments now `tert62/dsc-<svc>:<sha7>` (api-gateway `fbbcde1`, deploy-service `ede65da`, log-service `2ddc863`); both `migrate-job.yaml` still `…ECR…:v1` (no `-migrate` image on Docker Hub) |
| AC-7 | All shipped images live in one registry per environment, documented here | compare `image:` lines with §5 | **ACTIVE**: Docker Hub chosen for all targets (IRD-006 §1, 2026-10-12); remaining ECR refs = migrate Jobs only. Images are amd64-only → do not run on arm64 minikube (CI multi-arch gap) |
| AC-8 | No secret is baked into any image or committed `.env` | `docker history --no-trunc <image> \| grep -i pass` → empty; `.dockerignore` excludes `.env*` | DONE |
| AC-9 | Dev Compose uses the same Postgres/Redis major versions as DOP-001 §5 (18 / 8) | `grep -n 'image:' infra/docker-compose.yml` | **ACTIVE — violated**: Compose dev pins `postgres:16-alpine` / `redis:7-alpine` |

## 5. Tech stack

| Item | Value |
|---|---|
| Base image | `node:24-alpine` (builder + runtime) |
| Runtime user | `app` (system user/group created in runtime stage) |
| Health check | `node -e` HTTP GET `localhost:<port>/health`, 30 s interval, 3 retries |
| Ports | api-gateway 3000, deploy-service 3001, log-service 3002 |
| Registry (Compose prod / CI) | Docker Hub `tert62/dsc-<service>:<sha7>` |
| Registry (K8s, Day 17) | ECR `241533152550.dkr.ecr.us-west-2.amazonaws.com/<service>:v1` — **drift**, see AC-6/AC-7 |
| Local runtime | Docker Compose, networks `frontend` (gateway only) + `backend` (all) |
| Deploy script | `infra/scripts/deploy.sh <service> <tag>` — pull → restart (`--no-deps`) → health-gate 60 s → auto-rollback |
