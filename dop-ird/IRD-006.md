## 4. Data model — manifest skeleton (the agent copies this shape)

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: <svc>
  namespace: deploy-status-checker
  labels: { app: <svc> }
spec:
  replicas: 1                       # ≥2 once TIE-25/26/27 land
  strategy:
    type: RollingUpdate
    rollingUpdate: { maxUnavailable: 0, maxSurge: 1 }
  selector: { matchLabels: { app: <svc> } }
  template:
    metadata: { labels: { app: <svc> } }
    spec:
      containers:
        - name: <svc>
          image: <registry>/<svc>:<sha7>
          ports: [{ containerPort: <port> }]
          envFrom: [{ configMapRef: { name: <svc>-cm } }]
          env:
            - name: DATABASE_URL
              valueFrom: { secretKeyRef: { name: <svc>-secret, key: DATABASE_URL } }
          resources:
            requests: { cpu: 100m, memory: 128Mi }
            limits:   { cpu: 250m, memory: 256Mi }
          readinessProbe: { httpGet: { path: /health, port: <port> }, initialDelaySeconds: 10, periodSeconds: 10 }
          # livenessProbe: only if /health has no dependency (api-gateway)
```

## 5. Acceptance criteria

- AC-1: `kubectl get all -n default` shows only the `kubernetes` Service.
- AC-2: Every container in every app Deployment has both `requests` and `limits`.
- AC-3: Every app container has a `readinessProbe`; only api-gateway has a `livenessProbe`.
- AC-4: Every app Deployment declares `RollingUpdate` with `maxUnavailable: 0`.
- AC-5: `kubectl get svc -n deploy-status-checker` shows only `ClusterIP` (plus Helm-managed headless services).
- AC-6: No committed file under `*/k8s` contains a real credential or a `kind: Secret` with `data:` values.
- AC-7: Every image ref matches `…/<svc>:[0-9a-f]{7}` and contains no foreign account ID.
- AC-8: After `kubectl apply` of a new image, `kubectl rollout status` succeeds and `kubectl rollout undo` returns the previous ReplicaSet to Ready.
