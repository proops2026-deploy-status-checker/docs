# DOP-004 — Cloud Infrastructure

Project: Deploy Status Checker
Owner: Tien Nguyen (solo — no partner assigned)
Status: PARTIAL
Last audited: 2026-10-12
Parent: [DOP-001](DOP-001.md) (product) — this DOP takes over DOP-001 §6 and the AWS facts of §17.5.

## 1. Objective

Give Deploy Status Checker one known AWS home — one account, one region, tagged and cost-capped — where a staging/prod-equivalent environment can be created, verified, and fully torn down on demand without leaving billable orphans.

## 2. In scope

- AWS account, region, IAM principal, and the tag policy every resource must satisfy.
- Container registry location (ECR) and access.
- EKS cluster definition (`infra/eks/cluster.yaml`, `eksctl`).
- Staging-on-VM path (`infra/scripts/aws/provision-staging.sh`, TIE-23 — written, never executed).
- Cost guards and the teardown + orphan-check procedure.

## 3. Out of scope

- Kubernetes objects inside the cluster → [DOP-003](DOP-003.md).
- Terraform / Ansible codification of this infrastructure → [DOP-005](DOP-005.md).
- Production-grade VPC (private subnets + NAT), multi-region, multi-account org structure.
- IRSA/OIDC, AWS Load Balancer Controller, Cluster Autoscaler, Container Insights (training skip-list, `infra/memory/eks-practice.md` §5).

### Decision 2026-10-12 — one project account
- `868737222758` (`default`) is the **only** project account. Nothing project-related is planned in any other account.
- Day 17 used `241533152550` (profile `vsf-tien`) as a **one-off quick test**, because the guardrail here denies `iam:CreateRole` and `eksctl` cannot run (`infra/memory/eks-practice.md` §6 #2). That test is closed: cluster deleted, no live resources.
- Leftover from the test: every `*/k8s/*.yaml` image ref still points to `241533152550` ECR (AC-3). Those refs must move to the project account (or to local images for minikube) — they are drift, not a second home.
- Future EKS in this account needs an IAM grant for `iam:CreateRole`/`TagRole`. Until then, Kubernetes work runs on minikube.
