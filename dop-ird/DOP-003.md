# DOP-003 — Orchestration

Project: Deploy Status Checker
Owner: Tien Nguyen (solo — no partner assigned)
Status: ACTIVE
Last audited: 2026-10-12
Parent: [DOP-001](DOP-001.md) (product) — this DOP takes over DOP-001 §9, §17 and the Kubernetes mechanics of §10.

## 1. Objective

Run the three Deploy Status Checker services and their stateful dependencies on Kubernetes so that a bad Pod is taken out of traffic without a restart storm, a release can be rolled out and rolled back with one command, the database survives a primary loss, and the gateway is the only thing reachable from outside the cluster.

## 2. In scope

- Namespace `deploy-status-checker` holding every project object.
- App workloads: `api-gateway`, `deploy-service`, `log-service` as `Deployment` + `ClusterIP` `Service` + `ConfigMap` + `Secret` (manifests in each service repo's `k8s/`).
- Schema migrations as one-shot `Job`s (`migrate-job.yaml`, `migrator` image).
- Stateful dependencies via Helm: `bitnami/postgresql` (release `my-postgres`, `architecture: replication`), `bitnami/redis` (release `my-redis`, `standalone`, AUTH on).
- Public entry: `Ingress` `deploy-status-ingress` (class `nginx`, host `deploy-status.local`) → `api-gateway` only.
- Probe policy, apply order, ConfigMap-vs-Secret rule, in-cluster DNS naming.
- Clusters: `minikube` (dev / training) and EKS (prod-equivalent, see [DOP-004](DOP-004.md)).

## 3. Out of scope

- Autoscaling (HPA/KEDA) — DOP-001 §13 non-goal.
- Service mesh, canary / blue-green — DOP-001 §13 non-goals.
- Automatic Postgres failover (`postgresql-ha`/repmgr) — promotion stays operator-triggered (`pg_promote()`).
- GitOps (Argo CD / Flux) — not before Week 6.
- Cluster provisioning and AWS networking → [DOP-004](DOP-004.md).

## 5. Tech stack

| Item | Value |
|---|---|
| Kubernetes | EKS `1.33` (Day 17); minikube (dev) |
| Ingress controller | ingress-nginx (`ingressClassName: nginx`) |
| Storage | `gp3` StorageClass, `ebs.csi.aws.com`, default class (EKS) |
| Postgres | `bitnami/postgresql`, replication, 1 primary + 1 read, 1 Gi PVC each, preset `nano` |
| Redis | `bitnami/redis`, standalone, 1 Gi PVC, requests = limits 100m/250m CPU, 256 Mi |
| App resources | requests `100m` CPU / `128Mi` memory; limits **missing** |
| Rollout strategy | Deployment default (RollingUpdate 25 % / 25 %) — not declared explicitly |
| DNS | Short names inside the namespace: `my-postgres-postgresql-primary`, `-read`, `my-redis-master`, `deploy-service`, `log-service`, `api-gateway` |
| Apply order | namespace → Helm (Postgres, Redis) → app ConfigMap/Secret/Deployment/Service → migrate Jobs → Ingress (`infra/memory/kubernetes-project.md` §4) |
