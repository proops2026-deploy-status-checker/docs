## 1. Decision

| # | Decision | State on 2026-10-12 |
|---|---|---|
| 1 | Every service Dockerfile has a `builder` stage and a `runtime` stage; Prisma services add `migrator` (`FROM builder AS migrator`) | Ratified — already true |
| 2 | Every stage uses `node:24-alpine`. A base-image change is a DOP-001 §5 change first | Ratified |
| 3 | The runtime stage installs production deps only (`npm ci --omit=dev`) and copies only `dist/` plus the generated Prisma client | Ratified |
| 4 | The runtime stage runs as the non-root system user `app` (`USER app`) | Ratified |
| 5 | Every runtime image declares a `HEALTHCHECK` that GETs `localhost:<port>/health` | Ratified |
| 6 | `.dockerignore` excludes `node_modules`, `dist`, `.env`, `.env.*` (keeps `.env.example`) | Ratified (api-gateway checked) |
| 7 | Registry, image name and tag format are defined **only** in [IRD-004](IRD-004.md) §4 (one home per fact). This IRD only says: tag = 7-char git SHA, never `latest`, never a hand-made tag such as `v1` | **Not met** in `*/k8s/*.yaml` (`:v1`) |
| 8 | Images that run on a cluster are built `--platform=linux/amd64` (Apple Silicon laptops build arm64 by default) | Ratified (Day 17) |
| 9 | Stateful dependency images (Postgres, Redis) use the same major version everywhere: Compose dev, Compose prod, Helm (DOP-001 §5: 18 / 8) | **Not met** — Compose dev pins `postgres:16-alpine`, `redis:7-alpine` |

## 2. Inputs

| Input | Source |
|---|---|
| Source code + `package*.json` | service repo |
| `prisma/schema.prisma` | `deploy-service`, `log-service` |
| Build args | none — no build-time secrets or config are passed |
| Runtime config | env vars at `docker run` / Compose / K8s time (`.env.example` lists them); never baked in |

## 3. Outputs

| Output | Target | Used by |
|---|---|---|
| `<service>` runtime image | `runtime` (default, last stage) | Compose, K8s Deployment |
| `<service>-migrate` image | `--target migrator` | K8s migrate `Job`, one-shot Compose run |

## 4. Data model — image contract

| Service | Port | Health endpoint | Runtime user | Extra target |
|---|---|---|---|---|
| api-gateway | 3000 | `/health` (no dependencies) | `app` | — |
| deploy-service | 3001 | `/health` (queries Postgres) | `app` | `migrator` |
| log-service | 3002 | `/health` (queries Postgres) | `app` | `migrator` |

Rules the agent must follow:
- ALWAYS: pin the base image to a version tag; build `runtime` as the final stage so a plain `docker build` produces it.
- ALWAYS: copy `package*.json` before source so the `npm ci` layer is cached.
- NEVER: `ENV` a secret, `COPY .env`, or install the `prisma` CLI into `runtime`.
- NEVER: run as root, use `latest`, or add OS packages that the app does not need at runtime.

## 5. Acceptance criteria

- AC-1: Every Dockerfile has ≥ 2 `FROM` lines and the last one is `AS runtime`.
- AC-2: No `FROM` line uses `latest` or an unpinned image.
- AC-3: A running runtime container's UID is not 0.
- AC-4: Every runtime image reports a `Healthcheck` in `docker inspect` and turns `healthy` within 60 s when its dependencies are up.
- AC-5: The runtime image has no `prisma` binary.
- AC-6: No image reference under `*/k8s/` or `infra/docker-compose.prod.yml` uses a tag other than a 7-char SHA.
- AC-7: Compose dev Postgres/Redis majors equal DOP-001 §5.
