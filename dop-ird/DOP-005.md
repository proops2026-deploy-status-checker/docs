## 1. Objective

Every piece of Deploy Status Checker infrastructure that is created more than once is created by code that can be planned before it is applied, re-run without side effects, and dry-run before any state change.

## 2. In scope (known today)

- Terraform for AWS resources (first lab: `proops2026/iac/terraform/` — EC2 + SG + key pair, Day 20).
- Ansible for host configuration (`proops2026/iac/ansible/playbook.yml`, Day 20).
- Bash automation in `infra/scripts/` (`deploy.sh`, `backup-db.sh`, `restore-db.sh`, `generate-secrets.sh`, `rotate-db-roles.sh`, `aws/provision-staging.sh`).

## 3. Out of scope

- Kubernetes manifests and Helm values → [DOP-003](DOP-003.md).
- Pulumi / CDK / CloudFormation authored by hand.

## 4. Acceptance Criteria (draft — to be finalized Day 26)

| AC | Criterion | Verify with | Status 2026-10-12 |
|---|---|---|---|
| AC-1 | Terraform for this project lives in the project org (`infra` repo), not only in the trainee repo | `ls infra/terraform` | ACTIVE — lab code is in `proops2026/iac/` only |
| AC-2 | A second `terraform plan` after `apply` shows `No changes` | `terraform plan -detailed-exitcode` → exit 0 | DONE for the Day 20 lab |
| AC-3 | `tfstate`, `.terraform/`, real `*.tfvars` are never committed | `git check-ignore -v terraform.tfstate` | DONE for the Day 20 lab |
| AC-4 | A second Ansible run reports `changed=0` | playbook recap | DONE for the Day 20 lab |
| AC-5 | Every state-changing script supports `--dry-run` | `grep -L -- '--dry-run' infra/scripts/*.sh` → empty | ACTIVE — not audited yet |
| AC-6 | Remote state backend (S3 + `use_lockfile`) for shared environments | `terraform init` backend block | ACTIVE |
