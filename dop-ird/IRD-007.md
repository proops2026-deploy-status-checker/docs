# IRD-007 — Helm Chart Conventions

Implements: [DOP-003](DOP-003.md) (Orchestration)
Type: Standard (cross-cutting — third-party stateful dependencies installed with Helm)
Owner: Tien Nguyen
Status: ACTIVE
Last updated: 2026-10-12

Scope: Helm is used **only** for third-party stateful dependencies (Postgres, Redis). The three app services are plain `kubectl apply` manifests ([IRD-006](IRD-006.md)) — two lifecycles, two tools (old DOP-001 §17.2).

## 1. Decision

| # | Decision | State on 2026-10-12 |
|---|---|---|
| 1 | Releases: `my-postgres` (`bitnami/postgresql`) and `my-redis` (`bitnami/redis`), both in namespace `deploy-status-checker` | Ratified |
| 2 | One override file per release: `infra/k8s/my-<release>-values.yaml`. Only values that differ from the chart default go in it | Ratified |
| 3 | Postgres `architecture: replication` (1 primary + 1 read replica); Redis `architecture: standalone` with AUTH enabled | Ratified (TIE-28, Day 16) |
| 4 | Install and upgrade with the same idempotent command: `helm upgrade --install <release> <chart> --version <chart-version> -f <values> -n deploy-status-checker` | **New** — chart `--version` has never been pinned |
| 5 | The values file pins `image.tag` explicitly (majors per DOP-001 §5: Postgres 18, Redis 8). Bitnami's public catalog otherwise serves rolling `latest` | **Not met** (TIE-40) |
| 6 | No password in any values file. Passwords come from pre-created Secrets (`auth.existingSecret`) or `--set-file` at install time | **Not met** — `auth.postgresPassword` and the Redis password are plaintext dev values (TIE-40). `replicationPassword` is already passed via `--set-file` (compliant) |
| 7 | `infra/init/01-databases.sh` stays the single source for DB/user creation; passed with `--set-file 'primary.initdb.scripts.01-databases\.sh=infra/init/01-databases.sh'` (single quotes — the `\.` must reach Helm) | Ratified |
| 8 | After every install/upgrade, read the full `NOTES` output and re-check service hostnames; any rename means patching app `DATABASE_URL`/`REDIS_URL` Secrets, rolling the apps, and re-running migrate Jobs | Ratified (hit Day 16 and Day 17) |
| 9 | Persistence: 1 Gi PVC per StatefulSet, default StorageClass (`gp3` on EKS, `standard` on minikube); resource preset `nano` | Ratified |

## 2. Inputs

| Input | Source |
|---|---|

## 4. Data model — upgrade / rollback runbook

| Step | Command | Check |
|---|---|---|
| 1. Preview | `helm diff upgrade …` (plugin) or `helm template … \| kubectl diff -f -` | Only intended fields change |
| 2. Upgrade | `helm upgrade --install …` (Decision #4) | `helm status <release>` = `deployed` |
| 3. Read NOTES | — | Hostnames unchanged? If not → Decision #8 |
| 4. Verify | `kubectl get pods -n deploy-status-checker` | StatefulSet Pods `Running 1/1` |
| 5. Rollback (if needed) | `helm history <release>` → `helm rollback <release> <revision>` | — |
| 6. Unstick | If a Pod still runs the bad template: `kubectl delete pod <pod>` | Pod's `controller-revision-hash` = StatefulSet `status.updateRevision` (Day 16) |

## 5. Acceptance criteria

- AC-1: `helm list -n deploy-status-checker` shows exactly `my-postgres` and `my-redis`, both `deployed`.
- AC-2: Both values files contain an explicit `image.tag` with the DOP-001 §5 major.
- AC-3: No values file contains a literal password.
- AC-4: The install command in `infra/memory/kubernetes-project.md` §4 includes `--version`.
- AC-5: After an upgrade, app Pods reach Ready without manual Secret edits — or the NOTES-driven patch (Decision #8) is recorded.
- AC-6: `helm rollback` to the previous revision returns all StatefulSet Pods to Ready (Day 16 procedure).
